# Баг-репорт из 1.1: «нажимаю «Подъём» — сразу три уведомления, «после еды» тоже, потом «опоздание», спам»

Дата проверки: 14.09.2026, код 1.2.1. Статус: **частично актуально → выпущено как 1.2.2 (versionCode 5) 14.09.2026**.

## Сценарий

Три таблетки со смещением первого приёма «Сразу» (0 мин), одна из них — «сразу после еды». Нажатие «Подъём».

## Что делает код 1.2.1 (трассировка)

1. `Planner.wakeUpLocked` создаёт три приёма с `plannedAt = момент подъёма` и зовёт `rescheduleAlarmsLocked`.
2. Приём «после еды»: `mealSatisfied` = false (еды после подъёма нет; тест `MealGateTest.firstDoseWaitsWithoutMeal`).
   Будильник ставится на `plannedAt + 3 ч` (страховка). Карточка показывает «ждёт «Еда»», не краснеет.
   **Уведомление при подъёме не приходит — исправлено в 1.2.** Мягкое напоминание «Поели?» (1.2.1) для смещения 0
   не показывается: его момент совпадает с подъёмом, а пользователь и так видит карточку.
3. После «Еда» `applyIntakeConstraints` двигает приём на «еда + 1 мин», будильник звонит через минуту. Ожидание
   «минимум 20 минут» — это ожидание самой кнопки, оно соблюдается.
4. Два обычных приёма «Сразу»: время уже наступило → первый звонок через интервал повторов (3 мин), одним
   групповым уведомлением (плановое время совпадает), далее повторы каждые 3 мин до отметки — настройка «Повторы».

## Что всё ещё было не так

- **«Опоздание на 2 мин» сразу после подъёма.** `countdown()` пишет «сейчас» только в первую минуту, дальше — «опоздание».
  Приложение при этом само ещё ни разу не напомнило (первый звонок — через 3 мин). Пользователь читает это как упрёк.
- **Несколько цепочек повторов.** Группировка в `ReminderReceiver` объединяла только приёмы с одинаковой минутой
  планового времени. Приёмы «Сразу» и «+30 мин» (или приём, сдвинутый «Едой») звонили каждый своей цепочкой —
  два-три уведомления каждые три минуты. Это и есть «уведы спамят».

## Исправления 1.2.2

- Карточка: в первые `DUE_TEXT_GRACE_MS` (5 мин) после планового времени — «сейчас», потом «опоздание на N мин».
  Цвет (янтарный «ждёт приёма») не меняется — время действительно наступило.
- Уведомление: в группу попадает **всё, чему сейчас пора** (`plannedAt <= now + 1 мин`), кроме ждущих «Еда»,
  отложенных (`snoozedUntil`) и просроченных больше `OVERDUE_GRACE_MS` (они остаются в списке дня молча).
  Старший приём группы ведёт уведомление, остальные молчат и ждут своей очереди, как и раньше. Итог: один
  «Пора принять: 2 таблетки» каждые три минуты вместо двух-трёх параллельных.
- Сами повторы каждые 3 мин × 20 остаются настройкой («Настройки → Повторы»); при желании интервал можно увеличить.

## Дополнение: трекеры на одно время

Три трекера с опросом в 20:00 присылали три уведомления (id по трекеру) плюс, при совпадении, напоминание о таблетке.
Теперь `TrackerReceiver` собирает все трекеры, которым пора сейчас (время ± 1 мин, записи после предыдущего слота нет),
в одно уведомление «Пора записать: вес, настроение, сон» с фиксированным id — три ресивера в одну минуту перезаписывают
одну карточку. Канал отдельный, обычной важности: звук есть, всплывающей плашки нет, чтобы напоминание о таблетке
осталось главным. Слить трекеры в само уведомление о таблетке не стоит: у него кнопки «Выпито/Пропустить», и лишний
текст про вес их размывает.

## Не проверено на устройстве

Только сборка и юнит-тесты: одно групповое уведомление для приёмов с разным плановым временем и переход старшинства
после отметки одной из таблеток.
