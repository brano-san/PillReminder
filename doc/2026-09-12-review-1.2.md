## Планировщик и будильники (data/Planner.kt, MealGate.kt, alarm/*)

- P1 🔴 **`rescheduleAlarms()` затирает «Отложить» и цепочку повторов.** Любая мутация (и каждый запуск
  приложения) отменяет все будильники и для просроченного приёма ставит «сейчас + интервал повторов» или
  ничего. Отложенный на 15 мин приём звонит через 3 мин или не звонит вовсе. Исправление: поле
  `Dose.remindAt` (миграция 2→3 ещё открыта), выставляется при «Отложить» и при постановке следующего
  повтора, сбрасывается при отметке/сдвиге; `rescheduleAlarms` уважает `remindAt > now`.
- P2 🔴 **Новый «Подъём» через полночь оставляет ожидающие приёмы прошлого цикла с будильниками.**
  `wakeUp()` удаляет PENDING только за календарный день. Исправление: чистить PENDING предыдущего дня
  цикла (с отменой будильников и уведомлений); в `rescheduleAlarms` добавить день последнего пробуждения.
- P3 🔴 **Группировка уведомлений игнорирует ожидание еды.** Приём без правила молчит, если «лидер»
  группы ждёт «Еда». Исправление: фильтровать группу через `mealSatisfied()`.
- P4 🔴 **Ведомые приёмы группы теряют повторы**, когда лидер отмечен. Исправление: каждый ставит свой
  следующий повтор.
- P5 🔴 **`finishCourse()` оставляет завтрашний приём «по часам»; `rescheduleAlarms` звонит для
  неактивных таблеток.** Исправление: удалять PENDING за {день цикла, сегодня, завтра}; пропускать и
  удалять приёмы неактивных таблеток.
- P6 🔴 **`takeNow()` пишет на календарный день и не вызывает `rescheduleAlarms()`.** Исправление:
  `cycleDay()` + пересборка.
- P7 🔴 **`takeAllDue()` — календарный день и без учёта ожидания еды.** Исправление: `cycleDay()`,
  пропуск ждущих еду; кнопка на главной считает так же.
- P8 🟠 **«Еда» двигает уже звонящий приём вперёд, а уведомление остаётся в шторке.** Исправление:
  `Notifications.dismiss` для приёмов с `due > now`.
- P9 🟠 **«Выпито»/«Пропустить» с карточки не убирают уведомление.** Исправление: `dismiss` в
  `markTaken`/`markSkipped`.
- P10 🔴 **Редактирование таблетки после закрытого набора планирует фантомный набор в прошлом.**
  Исправление: закрытый в текущем цикле набор → ничего не планировать.
- P11 🔴 **`refreshMedToday` для связанной ищет только `indexInDay == 0` родителя** (второй цикл суток
  ломается). Исправление: последний выпитый приём родителя с `index % timesPerDay == 0`.
- P12 🔴 **Ручной сброс дня удаляет приёмы связанных и не пересоздаёт их.** Исправление: в `wakeUp()`
  перепланировать детей, у чьего родителя уже есть выпитый стартовый приём в этом цикле.
- P13 🔴 **Удаление/завершение родителя оставляет детей «сиротами»** (никогда не планируются, карточка
  «Всё выпито · 0 из N»). Исправление: снимать связь у детей при деактивации родителя.
- P14 🔴 **Параллельные `rescheduleAlarms` дублируют приёмы «по часам».** Исправление: `Mutex` на
  мутации планировщика; убрать дубль вызова в `App.onCreate` и `BootReceiver`.
- P15 🔴 **Правка «по часам» в цикле через полночь оставляет послезавтрашние приёмы на старом времени.**
  Исправление: удалять PENDING за {день, день+1, сегодня, завтра}.
- P16 🔴 **Истёкшие курсы «по часам» и связанных никогда не деактивируются.** Исправление: деактивация
  в `syncFixedSchedule`/`startLinkedMeds`.
- P17 🔴 **«Вернуть» для приёма «по необходимости» делает из него PENDING, который звонит.**
  Исправление: удалять такой приём (с возвратом остатка).
- P18 🟠 **Уведомление «Пора нажать «Подъём»» и тестовое несут мёртвые кнопки Выпито/Пропустить/Отложить.**
  Исправление: `withActions = false`.
- P19 🟠 **Групповое уведомление печатает количество всех приёмов формой лидера** («5 таблеток» для капель).
  Исправление: форма по каждой таблетке.
- P20 🔴 **Удаление PENDING без отмены будильников и уведомлений** — кнопка в шторке бьёт по удалённому id.
  Исправление: хелпер `dropPending(ids)`.
- P21 🔴 **Завтрак «удовлетворяет» приём «после еды» со смещением +6/+12 ч.** Исправление: для первого
  приёма набора еда учитывается не раньше чем за 3 ч до базового времени (`MEAL_LOOKBACK_MS`).
- P22 🔴 **После «Сон» приёмы закрытого цикла продолжают звонить, а экран говорит «день закончен».**
  Решение: не звонить для приёмов дня с `bedAt != null` (кроме «по часам»), уведомления снять.
- P23 🔴 **Три определения «цикл активен»** (Planner/VM с `bedAt`, WakeReminder и виджет — без).
  Исправление: `WakeEvent.isActive(now)` и единое использование.
- P24 🟠 **Пропуск первого приёма родителя не запускает связанных.** Исправление: запускать и при пропуске.
- P25 🟢 Комментарий `CYCLE_MAX_MS` говорит «23 часа», константа 18 ч; FEATURES.md тоже. Исправить.
- P26 🔴 **Отмена возвращает больше остатка, чем списали** (списание было обрезано нулём). Исправление:
  не обрезать при списании, обрезать при показе.

## Проверка на устройстве (13.09.2026)

Пользователь: схема дня выглядит хорошо, но нет горизонтальных линий между узлами. Причина — правка H7 из этого
ревью: `width(44.dp)` у соединителя заменили на `widthIn(min = 44.dp)`, а ряд прокручивается по горизонтали, то есть
максимальная ширина у детей бесконечная. `fillMaxWidth()` у линии без содержимого при бесконечном максимуме даёт
нулевую ширину. Исправлено: `widthIn(min).width(IntrinsicSize.Max)` — ширина ограничена подписью промежутка,
не меньше 44 dp. Автотестом Compose-раскладка не покрывается, проверка — на устройстве в 1.2.
