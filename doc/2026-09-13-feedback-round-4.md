## 1. 🐞 «После еды»: забыли нажать «Еда» — уведомления нет 3 часа

**Что сейчас.** Приём «через 30 мин после еды» ждёт кнопку «Еда» (`mealSatisfied`), будильник стоит на
`plannedAt + 3 ч`. Если человек поел и забыл нажать кнопку — телефон молчит три часа.

**Решение.** Будильник ставится на `plannedAt` как обычно. В `ReminderReceiver`, если приём ждёт еду
и с планового времени прошло меньше `MEAL_WAIT_MAX_MS`, показывается **напоминание о еде**:
«Эсциталопрам — ждёт кнопку «Еда». Поели — нажмите, напомним через 30 мин». Кнопки: «Еда» (`ACTION_MEAL` →
`planner.recordMeal()`), «Выпито». Без цепочки повторов: после показа `planner.rescheduleAlarms()`
переставляет будильник на `plannedAt + 3 ч` (страховка). Нажали «Еда» → `applyIntakeConstraints` двигает
приём на «еда + N» (это всегда будущее), старое уведомление снимается (`plannedAt > now`), обычное
напоминание придёт вовремя.

**Правило в `rescheduleAlarmsLocked`:** ждёт еду и `plannedAt > now` → будильник на `plannedAt`;
ждёт еду и время прошло → на `plannedAt + MEAL_WAIT_MAX_MS` (если ещё впереди, иначе — логика просрочки).
`dismiss` старого уведомления — только когда `plannedAt > now` (иначе гасили бы само напоминание о еде).
В `recordMeal` у ожидавших приёмов сбрасываются `remindAt`/`attempt`: план поменялся.

❓ Напоминание о еде идёт по обычному каналу (не будильник) и один раз — чтобы не превратиться в вторую цепочку.

## 3. 🐞 Шаг «Как часто»: итог не последний

Порядок секций: «По необходимости» → «Сколько раз в день» → «Когда напоминать» → «Промежуток» → «Через N дней»
→ **«Как долго длится курс»** → **итог** `HintCard(scheduleResult(...))`, куда добавляется « · курс N дней»
(`durationLabelShort`) при курсе > 0. Для «по необходимости» итог тоже показывается («Получается: по необходимости · курс 14 дней»).

## 4, 15. ✨ Схема дня — отдельная карточка, короткие подписи, тап по кружку

- Состояния: `TimelineState.DUE` (янтарный, наступило и < 2 ч) и `OVERDUE` (красный, ≥ 2 ч); отложенный приём
  (`remindAt > now && attempt == 0`) — `PENDING`.

## 8. ✨ «Отложить» на карточке

- `MedRow.snoozedUntil: Long?` = `next.remindAt`, если `attempt == 0 && remindAt > now` (только кнопка «Отложить»
  ставит `attempt = 0`; цепочка повторов передаёт `attempt ≥ 1`).
- Полный режим, ряд действий: `OutlinedButton(skip)` · `OutlinedIconButton(Snooze)` · `Button(took)`; меню `DropdownMenu`
  с `Settings.snoozeOptions` → `onSnooze(doseId, minutes)` → `vm.snooze` → `planner.snooze`. Кнопка есть, когда
  `next.plannedAt <= now`. Сокращённый режим — пункт в диалоге долгого нажатия.
- Карточка при `snoozedUntil`: подпись «отложено до 12:40», рамка янтарная, время не красное.

## 9, 21. ✨ Точки прогресса набора

`MedRow.setStatuses: List<DoseStatus?>` — статусы приёмов текущего набора по `indexInDay` (`null` — ещё не создан),
длина `totalToday`. `SetDots(statuses, nextIndex)`: 8 dp кружки через 4 dp; TAKEN — зелёный, SKIPPED — серый,
следующий — контур primary 2 dp, остальные — контур outline. `contentDescription = intakeOf(n, total)`.
В полном режиме — над кнопками, в сокращённом — первым элементом в ряду меток.

## 11, 14. 🐞 Красный цвет

- `OVERDUE_GRACE_MS` становится публичным: одна граница «просрочено критически» и для будильника, и для цвета.
- Карточка: `due = next.plannedAt <= now && !waitsMeal && snoozedUntil == null`; `late = due && now - plannedAt >= OVERDUE_GRACE_MS`
  (плюс `mealTimedOut`). Рамка: `done` → зелёная; закрытый набор с пропуском → янтарная; `late` → красная,
  контейнер `errorContainer`; `due` или отложено → янтарная; иначе — нет. Текст времени: `late` → error,
  `due` → янтарный текст (`0xFF9A6700` светлая / `0xFFFFC65C` тёмная тема), иначе onSurface.
- Тепловая карта: `DayHeat.pending`; клетка сегодня: всё выпито и нет ожидающих → зелёная, иначе `primaryContainer`
  с рамкой («в процессе»). Легенда дополняется.
- Серия: `streak == 0` → «Сегодня отличный день, чтобы начать серию» обычным текстом; `> 0` → «🔥 N дней без пропусков».
- Карточка трекера на главной: подзаголовок без красного.
