# Гайд для агента: неявные связи проекта

Это чек-лист инвариантов, которые НЕ проверяются компилятором. Нарушишь — приложение
соберётся, но сломается на устройстве или будет выглядеть неконсистентно.
Проходи по списку при каждом изменении.

## Локализация — самое частое

- **Ни одной строки литералом в UI.** Каждый видимый текст живёт в
  [ui/Lang.kt](app/src/main/java/tech/unispace/pillreminder/ui/Lang.kt): поле в
  `interface S` + реализация в `object RU` **и** `object EN`. Забудешь EN — не скомпилируется
  (это специально), но следи, чтобы перевод был осмысленным, а не заглушкой.
- Плюрализация по-русски — через `ruPlural(n, "день", "дня", "дней")`.
- Composable-код читает `Lang.s` (реактивно, перерисуется при смене языка).
  Ресиверы/виджет тоже читают `Lang.s` — код выставляется в `App.onCreate` и в
  `PillWidgetProvider.refresh`.
- `MED_FORMS` (RU-строки в БД) ↔ `S.forms` — соответствие **по индексу**. Новая форма
  выпуска = запись в оба списка на одинаковой позиции + ветка в `formIcon()` в
  HomeScreen.kt (и RU, и EN названия).

## Туториал и советы

- **Каждая крупная фича = слайд в туториале**: пара `title to body` в `S.tutorialSlides`
  (RU и EN) + иконка в списке `icons` в `ui/Onboarding.kt` на той же позиции.
  Туториал показывается при первом запуске (`Settings.tutorialSeen`) и из настроек.
- Советы пользователю (почему так делать) — пары в `S.tips` (RU и EN), экран `ui/Tips.kt`.

## Поля ввода и подсказки

- **Каждый `OutlinedTextField` передаёт `colors = fieldColors()`** (`ui/Fields.kt`), иначе
  плейсхолдер рисуется тем же цветом, что и введённый текст, и путает пользователя.
  Проверка: `grep -c "OutlinedTextField(" ui/*.kt` должен совпадать с
  `grep -c "colors = fieldColors()" ui/*.kt` для каждого файла.
- Даты и время — только `DateWheelDialog`/`TimeWheelDialog` (NotesScreens.kt), никаких
  текстовых полей «ДД.ММ.ГГГГ».
- Ряды чипов — `FlowRow` (переносятся), не `Row`.
- Нижние панели мастеров — `imePadding()`, чтобы кнопки не уезжали под клавиатуру.
- `LinearProgressIndicator` — с `gapSize = 0.dp, drawStopIndicator = {}`, иначе M3 рисует
  лишнюю «палочку» справа.

## База данных

- **Релиз 1.0 выпущен, схема v1 зафиксирована.** Destructive-фолбэков нет: любое изменение
  entity = `version++` в `@Database` + явная `Migration(from, to)` в `AppDatabase.MIGRATIONS`
  + новый json в `app/schemas/` (генерируется сборкой). Без миграции Room упадёт на старте
  у всех, кто обновился — это хуже, чем не выпустить фичу.
- `Settings` — SharedPreferences, переживают обновление сами; новое поле = дефолт в геттере.
- `versionCode` в build.gradle.kts поднимать на каждый выпуск (Android не установит обновление
  с тем же кодом), `versionName` — по смыслу; версия показывается внизу настроек.
- Новая сущность/поле = entity + DAO + регистрация в `@Database(entities=[...])` +
  **добавить в Backup.kt** (export И import), иначе бэкап молча потеряет данные.
  При изменении полей поднимать `Backup.JSON_VERSION`.
- `doses` — одновременно расписание и история: `PENDING` — план, `TAKEN`/`SKIPPED` — история.

## Будильники и уведомления

- Приёмы ставятся через `setAlarmClock` — единственный тип, который не троттлится
  (повторы раз в 1–3 минуты иначе разъедутся). Остальные напоминания —
  `setExactAndAllowWhileIdle`.
- **Каналы уведомлений неизменяемы после создания.** Смена звука = `channelVersion++`
  и пересоздание каналов с новым id (см. Notifications.createChannels). Никогда не
  пытайся «обновить» канал.
- `Planner.rescheduleAlarms()` — единая точка: она же обновляет виджет и будильник
  «я проснулся». Любая мутация расписания должна заканчиваться её вызовом.
- Новый BroadcastReceiver обязан быть в AndroidManifest.xml, иначе будильник молча
  не сработает. И его нужно восстановить в BootReceiver (перезагрузка стирает все будильники).
- Диапазоны requestCode PendingIntent'ов (пересечение = молчаливая перезапись чужого):
  - id дозы (int) — напоминания о приёмах (три action-интента различаются action+data);
  - 500_000+ — уведомления визитов; будильники визитов — `hashCode("visit-$id-$offset")`;
  - 700_000+ — «таблетки заканчиваются»;
  - 820_000 + trackerId·MAX_ASK_TIMES + slot — трекеры; 801_001 — напоминание «я проснулся».
- Повторы уважают тихие часы (`isQuiet`/`quietEndMillis` в ReminderReceiver.kt);
  новый тип повторяющегося уведомления должен тоже.
- Смещения напоминаний о визитах произвольные: при пересборке отменяются все из
  `Settings.visitOffsetsEver` (сеттер `visitOffsetsMinutes` его пополняет автоматически).

## Логика расписания (Planner.kt)

- Всё время отсчитывается от кнопки «я проснулся», не от календарных часов.
- Следующий приём = **фактическое** время «выпил» + интервал, не плановое.
- Связанные таблетки (`linkedToMedId`) не планируются утром — их день запускает
  `startLinkedMeds` при отметке первого приёма родителя.
- «Выпил» списывает `stockCount`; `undo` обязан вернуть списанное.
- `asNeeded`-таблетки не имеют расписания вообще — только `takeNow`.
- Промежуток по умолчанию задаёт `defaultIntervalMinutes(n)` в EditMedScreen.kt (2 → 12 ч, 3 → 8 ч,
  4 → 5 ч, ≥5 → 16 ч бодрствования ÷ (N−1)); смена числа приёмов идёт только через `setTimes()`.
- «Выпил» раньше плана более чем на `EARLY_TAKE_THRESHOLD_MS` (1 ч) — через диалог «Ещё рано»
  (`takeChecked` в MedCard). Новая кнопка отметки приёма обязана идти через него, а не звать `onTake` напрямую.

## UI-соглашения

- Мастер таблетки: шаги — `enum Step`, список `steps` строится динамически
  (шаг «промежуток» пропадает при одном приёме в день). Новый шаг = enum + ветка `when`.
- Название таблетки обязательно — блокируются «Далее», «Сохранить» и иконка в шапке.
- Долгое нажатие по карточке (таблетка/заметка/визит/каталог/запись трекера) =
  удаление через `ConfirmDeleteDialog`. Разрушительные действия («Сдвинуть», «Восстановить
  из бэкапа») — через AlertDialog с пояснением.
- Экран деталей сущности, которую могут удалить с другого экрана, обязан обрабатывать
  «сущности больше нет» (`LaunchedEffect { onDone() }`), иначе чёрный экран.
- Повторный тап по активной вкладке — no-op (`navigateTab`), иначе экран мигает.
- Вложенные вкладки — `HorizontalPager` + `TabRow`, синхронизированные (свайп работает).
- Календарь истории: кнопка «к сегодня» появляется только вне текущего месяца (`ChronoUnit.MONTHS.between`).
- Каждому подэкрану — свой Scaffold с TopAppBar и стрелкой назад; вкладкам — паддинги
  из `tabPadding`.
- Порядок нижних вкладок: Главная · Записи · Трекеры · История · Настройки —
  «полезное слева, редкое справа». **Больше пяти вкладок нельзя** (M3 NavigationBar);
  заметки, врачи и каталог живут внутри «Записей» (`RecordsScreen`, пейджер). Подписи
  вкладок — `labelSmall`, `maxLines = 1`, иначе «Настройки» переносится.
- Текст на кнопках и чипах — `maxLines = 1, softWrap = false`, иначе Compose переносит
  «Поде-литься» по слогам; ряд кнопок — `FlowRow`.
- Числовые поля (запас, доза) — `KeyboardType.Number` + фильтр `filter { it.isDigit() }`;
  единицы дозы — чипы, а не свободный текст.
- Перетаскивание списка: `animateItem(placementSpec = if (isDragging) null else spring())`,
  иначе элемент «телепортируется» при втором перетаскивании.
- Заметки в списке группируются по давности (`ageGroup`: Сегодня/Вчера/7 дней/30 дней/Давно).
- Тема — статичная палитра в `ui/theme/Theme.kt`, динамические цвета отключены намеренно;
  `NavigationBar(containerColor = surface, tonalElevation = 0.dp)`.
- Переходы NavHost — `EnterTransition.None`/`ExitTransition.None`: fade между вкладками
  «проглатывал» нажатия. Не возвращать анимацию без причины.
- Количество за приём — только через `Lang.s.pills(amount, med.form)` / `formatAmount(amount, form)`:
  слово зависит от формы выпуска («3 капли», а не «3 таблетки»). Новая форма = ветка в обоих `pills()`.
- Графики с сеткой (`LineChart(showGrid = true)`, `MultiLineChart`) обязаны получать `xLabels`
  (даты по оси X) — общий хелпер `DrawScope.drawXLabels`, полоса `X_LABELS_PAD`.
- Полноэкранный будильник: система открывает full-screen intent только при заблокированном экране;
  на разблокированном `Notifications.show` сам стартует `AlarmActivity`, если выдано
  «показ поверх других приложений» (`Settings.canDrawOverlays`). Карточка разрешения — в SoundSettingsScreen.
  Для этого в манифесте обязан быть `SYSTEM_ALERT_WINDOW` — без него приложения нет в системном списке.
- Главная имеет два режима карточек (`Settings.homeCompact`); новая информация на
  карточке должна учитывать оба.

## Сборка и релиз

- R8 включён. Если что-то падает только в release — проверь `isMinifyEnabled=false`;
  подтвердится — добавь keep-правило в proguard-rules.pro, а не выключай R8.
- Релиз подписан `release.jks` (пароли в keystore.properties, оба в .gitignore).
  **Файл ключа терять нельзя** — без него не выпустить обновление.
- Сборка: `./gradlew.bat assembleRelease`; проверка подписи —
  `apksigner verify DoseDay-<версия>-release.apk` (имя задаёт `applicationVariants` в build.gradle.kts).

## Чек-лист перед сдачей изменения

1. Все новые строки — в Lang.kt, RU + EN.
2. Крупная фича — слайд туториала (RU/EN + иконка).
3. Новый `OutlinedTextField` — `colors = fieldColors()`.
4. Новая сущность/поле БД → Backup.kt (export + import).
5. Новый ресивер → манифест + BootReceiver.
6. Мутация расписания → заканчивается `rescheduleAlarms()`.
7. `assembleDebug` без warnings (`Select-String "^w: file"`), затем `assembleRelease`.
8. В ответе пользователю: что не проверено на устройстве.
