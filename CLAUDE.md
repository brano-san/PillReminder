# Гайд для агента: неявные связи проекта

Список фич для ручной проверки — в [FEATURES.md](FEATURES.md); новая фича = строчка и там.

Это чек-лист инвариантов, которые НЕ проверяются компилятором. Нарушишь — приложение
соберётся, но сломается на устройстве или будет выглядеть неконсистентно.
Проходи по списку при каждом изменении.

## Локализация — самое частое

- **Ни одной строки литералом в UI.** Каждый видимый текст живёт в
  [ui/Lang.kt](app/src/main/java/tech/unispace/pillreminder/ui/Lang.kt): поле в
  `interface S` + реализация в `object RU` **и** `object EN`. Забудешь EN — не скомпилируется
  (это специально), но следи, чтобы перевод был осмысленным, а не заглушкой.
- Плюрализация по-русски — через `ruPlural(n, "день", "дня", "дней")`.
- Composable-код читает `Lang.s` (реактивно, перерисуется при смене языка).
  Ресиверы/виджет тоже читают `Lang.s` — код выставляется в `App.onCreate` и в
  `PillWidgetProvider.refresh`.
- `MED_FORMS` (RU-строки в БД) ↔ `S.forms` — соответствие **по индексу**. Новая форма
  выпуска = запись в оба списка на одинаковой позиции + ветка в `formIcon()` в
  HomeScreen.kt (и RU, и EN названия). Так же по индексу: `WidgetStyle.presets` ↔ `S.widgetColorNames`.
- Связь с едой печатается **только** через `Lang.s.mealRelation(after, before, kcal)` (карточка,
  `previewFacts`, шторка, виджет). `MEAL_NOW` (1 минута = «сразу») живёт в Entities.kt и словами становится
  только там — никаких `duration(afterMealMinutes)` напрямую, иначе снова будет «через 1 мин после еды».

## Туториал и советы

- **Каждая крупная фича = слайд в туториале**: пара `title to body` в `S.tutorialSlides`
  (RU и EN) + иконка в списке `icons` в `ui/Onboarding.kt` на той же позиции.
  Туториал показывается при первом запуске (`Settings.tutorialSeen`) и из настроек.
- Советы пользователю (почему так делать) — пары в `S.tips` (RU и EN), экран `ui/Tips.kt`.

## Поля ввода и подсказки

- **Каждый `OutlinedTextField` передаёт `colors = fieldColors()`** (`ui/Fields.kt`), иначе
  плейсхолдер рисуется тем же цветом, что и введённый текст, и путает пользователя.
  Проверка: `grep -c "OutlinedTextField(" ui/*.kt` должен совпадать с
  `grep -c "colors = fieldColors()" ui/*.kt` для каждого файла.
- Даты и время — только `DateWheelDialog`/`TimeWheelDialog` (NotesScreens.kt), никаких
  текстовых полей «ДД.ММ.ГГГГ».
- Ряды чипов — `FlowRow` (переносятся), не `Row`.
- Нижние панели мастеров — `imePadding()`, чтобы кнопки не уезжали под клавиатуру.
- `LinearProgressIndicator` — с `gapSize = 0.dp, drawStopIndicator = {}`, иначе M3 рисует
  лишнюю «палочку» справа.

## База данных

- Схема v4, релиз 1.2.1 выпущен 13.09.2026 — **`MIGRATION_1_2`, `MIGRATION_2_3` и `MIGRATION_3_4` зафиксированы**.
  Любое новое поле = `version = 5` + отдельная `Migration(4, 5)`; дописывать в 3 → 4 больше нельзя.
  `fallbackToDestructiveMigrationOnDowngrade` оставлен.
- **Релиз 1.0 выпущен, схема v1 зафиксирована.** Destructive-фолбэков нет: любое изменение
  entity = `version++` в `@Database` + явная `Migration(from, to)` в `AppDatabase.MIGRATIONS`
  + новый json в `app/schemas/` (генерируется сборкой). Без миграции Room упадёт на старте
  у всех, кто обновился — это хуже, чем не выпустить фичу.
- `Settings` — SharedPreferences, переживают обновление сами; новое поле = дефолт в геттере.
- `versionCode` в build.gradle.kts поднимать на каждый выпуск (Android не установит обновление
  с тем же кодом), `versionName` — по смыслу; версия показывается внизу настроек.
- Новая сущность/поле = entity + DAO + регистрация в `@Database(entities=[...])` +
  **добавить в Backup.kt** (export И import), иначе бэкап молча потеряет данные.
  При изменении полей поднимать `Backup.JSON_VERSION`.
- `doses` — одновременно расписание и история: `PENDING` — план, `TAKEN`/`SKIPPED` — история.

## Будильники и уведомления

- Приёмы ставятся через `setAlarmClock` — единственный тип, который не троттлится
  (повторы раз в 1–3 минуты иначе разъедутся). Остальные напоминания —
  `setExactAndAllowWhileIdle`.
- **Каналы уведомлений неизменяемы после создания.** Смена звука = `channelVersion++`
  и пересоздание каналов с новым id (см. Notifications.createChannels). Никогда не
  пытайся «обновить» канал.
- `Planner.rescheduleAlarms()` — единая точка: она же обновляет виджет и будильник
  «я проснулся». Любая мутация расписания должна заканчиваться её вызовом.
- **Planner сериализует мутации `Mutex`**: публичные методы берут замок и зовут `*Locked`-варианты; внутри
  друг друга — только `*Locked` (Mutex не реентерабелен). Новый публичный метод = обёртка `lock.withLock { }`.
- **Будильники из ресиверов ставятся только через Planner** (`snooze()`, `rememberRepeat()`): момент и номер
  повтора живут в `Dose.remindAt`/`Dose.attempt`, иначе пересборка будильников их затирает. Прямой
  `AlarmScheduler.schedule` вне Planner запрещён. План сдвинулся → `remindAt = null, attempt = 0`.
- Удаление ожидающих приёмов — только `dropPending()`: он снимает будильник и уведомление, иначе кнопка в
  шторке бьёт по несуществующему id.
- «Цикл активен» — одно определение `WakeEvent.isActive(now)` (Planner, ViewModel, виджет, WakeReminder).
  После «Сон» цикла нет: интервальные приёмы дня снимаются, карточки и виджет показывают только «по часам».
- Деактивация таблетки (`finishCourse`/удаление) идёт через `deactivateLocked`: снимает её приёмы и отвязывает
  детей (`linkedToMedId = null`), иначе связанные никогда не планируются.
- Новый BroadcastReceiver обязан быть в AndroidManifest.xml, иначе будильник молча
  не сработает. И его нужно восстановить в BootReceiver (перезагрузка стирает все будильники).
- Диапазоны requestCode PendingIntent'ов (пересечение = молчаливая перезапись чужого):
  - id дозы (int) — напоминания о приёмах (action-интенты «Выпито/Пропустить/Отложить/Еда» различаются action+data);
  - 500_000+ — уведомления визитов; будильники визитов — `hashCode("visit-$id-$offset")`;
  - 700_000+ — «таблетки заканчиваются»;
  - 820_000 + trackerId·MAX_ASK_TIMES + slot — будильники трекеров; уведомление трекеров одно, id 820_000
    (`Notifications.showTrackers`, канал `CHANNEL_TRACKERS` обычной важности; кому пора — `trackerSlotAt`/`trackerNeedsEntry`);
    801_001 — напоминание «я проснулся»;
  - 900_001 — уведомление «день закрыт»; 960_000 + id дозы — кнопка «Выпито» на виджете (data `pill://widget/<id>`).
- Уведомления объединяются по признаку «пора сейчас» (`ReminderReceiver`: `plannedAt <= now + 1 мин`, не ждёт «Еда»,
  не отложен, не просрочен больше `OVERDUE_GRACE_MS`), а не по одинаковой минуте плана — иначе приёмы «Сразу» и «+30 мин»
  звонят двумя параллельными цепочками. «Старший» (меньший id) приём группы ведёт уведомление (`Notifications.showGroup`),
  ведомые снимают своё одиночное уведомление и молчат, продолжая свою цепочку.
- Повторы уважают тихие часы (`isQuiet`/`quietEndMillis` в ReminderReceiver.kt);
  новый тип повторяющегося уведомления должен тоже.
- Смещения напоминаний о визитах произвольные: при пересборке отменяются все из
  `Settings.visitOffsetsEver` (сеттер `visitOffsetsMinutes` его пополняет автоматически).

## Логика расписания (Planner.kt)

- Всё время отсчитывается от кнопки «я проснулся», не от календарных часов.
- «День» плавающий: он живёт от последнего пробуждения до `CYCLE_MAX_MS` (18 ч) или до нажатия «Ложусь спать» (`WakeEvent.bedAt`), а не до
  полуночи. Текущий день дают `Planner.currentCycle/cycleDay` и `cycleFlow` во ViewModel;
  всё, что раньше брало `today()`, должно спрашивать цикл. Когда все приёмы отмечены —
  `notifyDayDoneIfNeeded` шлёт уведомление, а на главной появляется «Начать новый день».
  Ручной сброс — долгое нажатие на карточку пробуждения (специально спрятан).
- Ограничения («после еды», «разносить») считаются от `Dose.baseAt`, двигают только вперёд,
  ограничены сверху (2 × интервал) и не трогают приёмы «по часам». Правило, двигающее назад,
  добавлять нельзя — иначе пересчёт зациклится.
- Еда: `recordMeal()` пишет `MealEvent`, а `applyIntakeConstraints` двигает ожидающие приёмы
  под `afterMealMinutes` и `apartFromOthersMinutes`. Двигаем только вперёд и только PENDING.
- **«После еды» ждёт «Поел»**: `mealSatisfied()` (data/MealGate.kt) — единственный судья и для будильника
  (`rescheduleAlarms`), и для карточки (`MedRow.waitsMeal` во ViewModel); считать по-разному нельзя, иначе
  экран и звонок разойдутся. Порог — подъём дня для первого приёма набора, иначе фактическое время предыдущего
  приёма этой таблетки. Без еды приём звонит только через `MEAL_WAIT_MAX_MS` (3 ч) после базового времени.
- Следующий приём = **фактическое** время «выпил» + интервал, не плановое.
- Связанные таблетки (`linkedToMedId`) не планируются утром — их день запускает
  `startLinkedMeds` при отметке первого приёма родителя.
- «Выпил» списывает `stockCount`; `undo` обязан вернуть списанное.
- `asNeeded`-таблетки не имеют расписания вообще — только `takeNow`.
- Расписание «по часам» (`Medication.fixedTimes`, CSV минут от полуночи): приёмы не зависят от
  кнопки «я проснулся». Их досоздаёт `syncFixedSchedule()` на сегодня и завтра — она вызывается
  в начале `rescheduleAlarms()`, поэтому любая точка входа (старт приложения, смена суток,
  BootReceiver, отметка приёма) поддерживает расписание живым. `shiftFollowing` такие приёмы
  не двигает: время фиксировано.
- Просроченный больше чем на `OVERDUE_GRACE_MS` (2 ч) приём будильником не озвучивается —
  остаётся в списке дня молча. **Та же константа делит цвета**: наступил и < 2 ч — янтарный (`DUE`), ≥ 2 ч — красный
  (`OVERDUE`) на карточке (`MedCard`) и схеме дня (`TimelineState`). До времени — нейтрально; красить пока не просрочено нельзя.
- **Напоминание о еде**: приём «после еды» без «Еда» в плановое время получает `Notifications.showMealPrompt` (кнопки
  «Еда» = `ACTION_MEAL` → `recordMeal()`, «Выпито»), без цепочки повторов; `rescheduleAlarmsLocked` при `plannedAt <= now`
  ставит страховку на `plannedAt + MEAL_WAIT_MAX_MS`, а `dismiss` делает только для `plannedAt > now` — иначе гасил бы само
  напоминание. `recordMeal()` сбрасывает `remindAt/attempt` ожидавших приёмов.
- **«Отложить» с карточки** = `Planner.snooze()` (attempt = 0). `Dose.snoozedUntil(now)` (DayTimeline.kt) — единственный
  признак «отложено» для карточки и схемы: `remindAt` с `attempt > 0` — это цепочка повторов, не отложенное.
- Промежуток по умолчанию задаёт `defaultIntervalMinutes(n)` в EditMedScreen.kt (2 → 12 ч, 3 → 8 ч,
  4 → 5 ч, ≥5 → 16 ч бодрствования ÷ (N−1)); смена числа приёмов идёт только через `setTimes()`.
- «Выпил» раньше плана более чем на `EARLY_TAKE_THRESHOLD_MS` (1 ч) — через диалог «Ещё рано»
  (`takeChecked` в MedCard). Новая кнопка отметки приёма обязана идти через него, а не звать `onTake` напрямую.

## UI-соглашения

- Мастер таблетки: шаги — `enum Step` (название · форма и заметка · количество · как часто и как долго ·
  когда и с чем пить · итог). Новый шаг = enum + ветка `when`. Последний шаг — только сводка,
  чтобы её было видно без прокрутки. Каждая смысловая группа внутри шага — `SectionCard`.
- Долгое нажатие по карточке заметки/визита/каталога/записи трекера = удаление через
  `ConfirmDeleteDialog`; по карточке таблетки — выбор «Дублировать / Удалить». Разрушительные действия («Сдвинуть», «Восстановить
  из бэкапа») — через AlertDialog с пояснением.
- Экран деталей сущности, которую могут удалить с другого экрана, обязан обрабатывать
  «сущности больше нет» (`LaunchedEffect { onDone() }`), иначе чёрный экран.
- Повторный тап по активной вкладке — no-op (`navigateTab`), иначе экран мигает.
- Вложенные вкладки — `HorizontalPager` + `TabRow`, синхронизированные (свайп работает).
- Календарь истории: кнопка «к сегодня» появляется только вне текущего месяца (`ChronoUnit.MONTHS.between`).
- Каждому подэкрану — свой Scaffold с TopAppBar и стрелкой назад; вкладкам — паддинги
  из `tabPadding`. Заметка и визит — одноэкранные формы без пейджера (мастер по шагам — только у таблетки).
- Визит: `DoctorVisit.remind = false` → `VisitAlarms.reschedule` только отменяет его будильники; список моментов на экране —
  `visitReminderMoments()` (чистая, тест), те же смещения `Settings.visitOffsetsMinutes`.
- Порядок нижних вкладок: Главная · Записи · Трекеры · История · Настройки —
  «полезное слева, редкое справа». **Больше пяти вкладок нельзя** (M3 NavigationBar);
  заметки, врачи и каталог живут внутри «Записей» (`RecordsScreen`, пейджер). Подписи
  вкладок — `labelSmall`, `maxLines = 1`, иначе «Настройки» переносится.
- Текст на кнопках и чипах — `maxLines = 1, softWrap = false`, иначе Compose переносит
  «Поде-литься» по слогам; ряд кнопок — `FlowRow`.
- Числовые поля (запас, доза) — `KeyboardType.Number` + фильтр `filter { it.isDigit() }`;
  единицы дозы — чипы, а не свободный текст.
- Перетаскивание списка: `animateItem(placementSpec = if (isDragging) null else spring())`,
  иначе элемент «телепортируется» при втором перетаскивании.
- Заметки в списке группируются по давности (`ageGroup`: Сегодня/Вчера/7 дней/30 дней/Давно).
- Графики трекеров: `LineChart(range = chartRange(type, values), smooth = Settings.chartSmooth)`.
  Сетка рисуется всегда (в мини-режиме пунктиром), шкала оценок фиксирована 0–5.
- Тема — статичная палитра в `ui/theme/Theme.kt`, динамические цвета отключены намеренно;
  `NavigationBar(containerColor = surface, tonalElevation = 0.dp)`.
- Переходы NavHost — `EnterTransition.None`/`ExitTransition.None`: fade между вкладками
  «проглатывал» нажатия. Не возвращать анимацию без причины.
- Количество за приём — только через `Lang.s.pills(amount, med.form)` / `formatAmount(amount, form)`:
  слово зависит от формы выпуска («3 капли», а не «3 таблетки»). Новая форма = ветка в обоих `pills()`.
- Графики с сеткой (`LineChart(showGrid = true)`, `MultiLineChart`) обязаны получать `xLabels`
  (даты по оси X) — общий хелпер `DrawScope.drawXLabels`, полоса `X_LABELS_PAD`.
- Полноэкранный будильник: система открывает full-screen intent только при заблокированном экране;
  на разблокированном `Notifications.show` сам стартует `AlarmActivity`, если выдано
  «показ поверх других приложений» (`Settings.canDrawOverlays`). Карточка разрешения — в SoundSettingsScreen.
  Для этого в манифесте обязан быть `SYSTEM_ALERT_WINDOW` — без него приложения нет в системном списке.
- Записи сна, собранные кнопками «Ложусь спать» → «Я проснулся», помечаются `auto = true`:
  на графике они рисуются контуром, а оценку можно поставить позже кнопкой «Оценить».
- Новая таблетка из мастера автоматически заводится в каталоге (MainViewModel.save), если
  записи с таким названием ещё нет.
- Клавиатура: `windowSoftInputMode=adjustResize` в манифесте, `@color/window_bg`
  (values + values-night) как `android:windowBackground` и Surface на всё окно в MainActivity —
  иначе под клавиатурой видна чёрная полоса.
- Нижняя кнопка главного экрана — один слот на цикл: «Я проснулся», пока день не начат,
  и «Ложусь спать», пока идёт. Блок «Отчёт · Советы · Туториал» — последний `item` ленты (после трекеров),
  прячется настройкой `Settings.showHomeActions`.
- В макетах виджетов можно использовать только классы с аннотацией `@RemoteView`
  (LinearLayout, RelativeLayout, FrameLayout, TextView, Button, ImageView…). `Space` и `View`
  запрещены: виджет перестаёт добавляться вообще.
- Виджетов два: `PillWidgetProvider` (макет widget_pills) и `PillWidgetWideProvider`
  (widget_pills_wide с подстроками `widget_sub1/2` и кнопкой «Выпил»). Логика одна — `PillWidgetProvider.refresh`
  рисует каждому свой макет; обе строки приёмов показываются в обоих вариантах.
- Фон виджета — `ImageView widget_bg` под содержимым: цвет `setInt(bg, "setColorFilter", …)`, прозрачность
  `setInt(bg, "setImageAlpha", …)`, цвет текста — `WidgetStyle.lightText`. `setBackgroundColor` не использовать:
  теряются скруглённые углы. `widget_bg.xml` остаётся бирюзовым — превью в системном списке рисует XML без кода.
  Любая настройка виджета заканчивается `PillWidgetProvider.refresh(context)`.
- Настройки виджета — свой экран `WidgetSettingsScreen` (маршрут `setup/widget`), пункт меню — `SettingsNavCard`.
  Предпросмотр берёт строки из `PillWidgetProvider.loadData()` (suspend, общий с самим виджетом). Режима текста «авто»
  нет: `Settings.widgetText` читает старое `auto` как `WidgetStyle.textModeFor(color)`; палитра `WidgetStyle.presets`
  ↔ `S.widgetColorNames` по индексу (тест).
- Схема дня на главной — `buildTimelineNodes()` (чистая функция, с тестом) + `DayTimeline` (ui/DayTimeline.kt), отдельная
  карточка под карточкой дня. Новый тип события дня = значение `TimelineKind` + ветки иконки и подписи в `TimelineNodeView`.
  Подпись таблетки — только `timelinePillLabel(name, doseInfo)`; тап по кружку → `onPillTap(medId)` → подсветка карточки
  (`highlightMedId`, индекс для прокрутки считает число элементов перед списком — новый `item` перед карточками = +1 там).
- Точки прогресса набора — `setStatuses(set, size)` (MainViewModel.kt, тест) + `SetDots`; строка «Приём N из M» осталась
  только как `contentDescription`.
- Дозировка и количество на карточке, в итоге мастера и на виджете — только `s.amountFact(amount, form, doseInfo)`
  («10 мг × 2 таб.»); метка формы словами — только для своей формы (не из `MED_FORMS`). Калории — внутри метки «после еды».
- Порядок таблеток — `ReorderDialog` (стрелки) из меню долгого нажатия; перетаскивания в `LazyColumn` нет и возвращать его
  не надо: `detectDragGestures` + `animateItem` конфликтовали с прокруткой («телепорт»).
- Счётчик «N из M» на карточке — через срез `currentSet(doses, size)` (MainViewModel.kt): набор — по номерам
  `indexInDay`, а не по модулю выпитых; «по необходимости» считает все приёмы дня. Серия дней — `streakDays()`.
- Из UI виджет обновляется `PillWidgetProvider.refreshAsync(context)`: `refresh` блокирует поток запросом к базе.
- Имена кнопок в текстах: RU «Подъём», «Сон», «Еда», «Выпито», «Принять сейчас»; EN "I woke up", "Sleep", "Ate",
  "Taken", "Take now". Формы без рода («Поел», «Лёг», «Выпил» — нельзя). Форма выпуска в тексте — `s.formName(form)`.
- Пункт чек-листа доставки `StepCard(done: Boolean?)`: `null` — нейтральный значок для непроверяемого или
  необязательного пункта; красный — только для обязательного и не выданного.
- История версий — `ui/Changelog.kt`, открывается нажатием на строку версии внизу настроек.
  Новый релиз = запись сверху с датой; невыпущенная версия — с пустой датой.
- Главная имеет два режима карточек (`Settings.homeCompact`); новая информация на
  карточке должна учитывать оба.
